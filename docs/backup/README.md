# Резервное копирование PostgreSQL

С 2025-10-12 в compose-стенде автоматически работает сервис `postgres-backup`, создающий аварийные дампы основной БД `asfp`. Резервирование выполняется раз в час и сохраняет данные до ручного удаления.

## Где искать дампы

- Каждые 60 минут запускается `pg_dump` с параметрами из `deploy/.env` (`POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `POSTGRES_HOST`, `POSTGRES_PORT`).
- Файлы записываются в каталог `backups/` в корне репозитория. Имя формируется как `asfp_YYYYMMDD_HHMMSS.sql`.
- Перед стартом контейнер гарантированно создаёт папку `backups/`, поэтому лицензии на запись не требуются.

## Как изменить расписание

- По умолчанию интервал равен одному часу (`BACKUP_INTERVAL_SECONDS=3600`).
- Чтобы изменить частоту, задайте переменную `BACKUP_INTERVAL_SECONDS` в `deploy/.env` и перезапустите стек (`make restart` или `docker compose ... restart postgres-backup`).

## Восстановление

1. Остановите сервисы, использующие БД (минимум `gateway`, `crm`, `wms`, `analytics`, `postgres-backup`).
2. Очистите схему или создайте новую БД при необходимости (через `psql` или `dropdb`/`createdb`).
3. Выполните `psql -h postgres -U asfp -d asfp -f backups/<имя дампа>.sql` из контейнера `postgres` или с хоста, где доступен `psql`.
4. Перезапустите сервисы (`docker compose ... up -d`).

## Ротация

Автоматическое удаление бэкапов не выполняется. Отдельная команда или администратор должны контролировать заполнение диска и удалять устаревшие дампы вручную.

## Отключение

- Если бэкапы не нужны, добавьте в локальный `docker-compose.override.yml` блок с `postgres-backup: { scale: 0 }` или полностью удалите сервис из override-файла.
